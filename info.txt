Вариант 2. Разделение репозиториев (Правильный подход)

Сейчас, скорее всего, у вас в VS Code настроен git push напрямую в удаленный репозиторий Amvera (например, git push amvera master).
Чтобы пушить код в процессе разработки, но не трогать живой сервер Amvera, используйте свой публичный GitHub как «промежуточный буфер»:
1. Для сохранения кода в процессе разработки: делайте пуш только на GitHub:bash
git push origin main
Используйте код с осторожностью.
2. Для деплоя на Amvera (только когда бот реально должен обновиться): делайте пуш в удаленный репозиторий Amvera:bash
git push amvera main:master
Используйте код с осторожностью.
Если вы вообще хотите временно запретить Amvera реагировать на пуши, просто удалите (или переименуйте) remote-адрес Amvera в локальном Git через VS Code:
bash
git remote remove amvera
Используйте код с осторожностью.
Когда бот снова понадобится, вы добавите его одной командой обратно.
